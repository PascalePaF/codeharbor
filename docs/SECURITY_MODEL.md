# 安全模型

## 保护目标

- 静态存储中的邮箱凭据和 TOTP 密钥不以明文出现。
- 邮件访问为只读，不改变邮件已读状态或服务器内容。
- 界面层即使出现普通前端错误，也不能直接访问文件系统或 Node.js API。
- 网络连接拒绝无效证书，并要求 TLS 1.2 或更高版本。

## 操作系统加密

- Windows：DPAPI，通常只有同一 Windows 登录凭据可以解密。
- macOS：Keychain。
- Linux：系统密钥环。检测到 `basic_text` 弱后端时拒绝保存秘密。

该保护主要防止磁盘文件被直接复制后读取。它不防御已经在同一用户会话中运行的恶意程序、管理员权限攻击、键盘记录器、屏幕录制或剪贴板窃取。

## 邮件内容

CodeHarbor 在主进程内存中解析最多 1 MiB 的邮件片段，只把发件人、时间、账户、用途和验证码候选返回界面。主题和正文不进入渲染结果，也不建立本地完整邮件数据库。候选必须出现在登录或身份验证语境附近，普通邮件中的订单号和跟踪号会被忽略。

## OAuth2

V1.0.2 把用户提供的访问令牌视为邮箱凭据并加密保存，但不实现浏览器授权、客户端注册或刷新令牌。访问令牌到期后需要用户手动更新。

## 跨电脑备份

- `.chbackup` 使用随机 16 字节盐、scrypt（N=16384、r=8、p=1）和 AES-256-GCM。
- 加密信封不包含明文邮箱凭据或 2FA 密钥；GCM 标签用于发现错误密码和文件篡改。
- 备份密码不写入本地保险库；忘记密码后无法恢复备份。
- 解密与系统安全存储的重新加密只在 Electron 主进程中进行。
- 导入文件限制为 25 MiB，邮箱与 2FA 各限制 500 项。
- 邮箱、2FA 可各自独立导出；分范围导入不会覆盖目标电脑的其他范围和设置。

## 自动更新

安装版只从项目配置的公开 GitHub Releases 获取版本元数据和构建产物，并验证 `latest.yml` 中的 SHA-512。更新下载与安装在 Electron 主进程完成；渲染进程不能指定任意更新源。便携版和开发环境不执行自动替换。

## 安装目录数据

用户要求数据跟随安装位置，因此 `vault.json` 默认位于程序目录的 `CodeHarbor-Data`。安装版卸载会保留该目录，但磁盘损坏、人工删除或第三方卸载工具仍可能造成损失；升级、移动和卸载前应导出完整加密备份。

## 剪贴板

点击验证码会写入系统剪贴板。Windows 剪贴板历史、同步剪贴板或第三方剪贴板管理器可能继续保留该值；高敏感场景下应在使用后清空剪贴板。

## 不在威胁模型内

- 已被攻陷的操作系统或同用户权限恶意软件。
- 邮箱服务商、网络端点或账户本身已失陷。
- 用户主动导出、截图或分享明文凭据。
- 利用大量账户规避第三方平台的使用规则。
